## 3. 主题与设定

### 3.1 一句话概念

> 一团火从雷击的树上被取下，十万年后离开地球。它从未熄灭，因为总有人接住它。

### 3.2 核心设定：同一团火

- **火不可复制**。它的价值不在于它是火，而在于它的**连续性**。复制一团一模一样的火当然可以，但那不是"它"。
- **载体死而火不死**。火把烧完、陶罐碎裂、锅炉报废，每一关结束时载体被消耗，火交到下一个载体上。
- **主角是流动的，火是恒定的**。每关玩家扮演不同时代的人，交接发生在关卡之间。玩家的身份是流动的，只有火是恒定的。
- **传递者看不到终点**。每一关的主角都不会知道火最终去了太空。

### 3.3 失败与重试的叙事处理

火灭了不是"你输了重来"，而是十万年的连续性差点断在你手上。**不要把重试解释为时间倒流**——每次濒死都是真实的，火确实差点熄灭，但被抢救回来了。关卡内的检查点就是基座/篝火，其叙事含义是"火曾在此驻留"。

### 3.4 镜头规则：永远聚焦火种

这是本项目最独特的表现手法，也是最大的技术风险点。

- 摄像机的锚点不是玩家角色，而是**火**
- 关卡转场**不需要切镜头**：镜头锁死在篝火上，时代在它周围流走
- **与题目第 3 条（第三人称）的冲突必须解决**：火脱手时若镜头只跟火，玩家会跑出画面，操作失控

**解决方案**：注视点 = 玩家与火的**加权中点**，火越远权重越高，同时拉远 FOV 保证两者都在框内；火脱手超过阈值时镜头明确偏向火，并给玩家方向指示。
**仅在过场时刻**镜头才真正脱离玩家、完全锁死在火上——那一刻的镜头行为变化本身就是叙事（"你不再重要了，火才重要"）。

### 3.5 视觉与美术约束

- 全部白模几何体，颜色编码区分材料特性
- **全部美术预算集中于火种特效**——它是唯一需要被看清的东西
- 火种特效同时承担：状态可读、燃料余量可读、经历可读 → 它是**零 HUD 的核心 UI**
- 所有火（手上的、地上的、炉里的）**共用同一套特效资产，仅参数不同**
- 不做音效音乐

## 4. 三条公理

**这是整个设计的地基。三关之间不新增规则，只新增材料。**

### 公理 I — 燃料即时间
火寄居在载体上，载体被持续消耗。**稀缺的不是火，是能烧的东西。**
- 点燃别人不会让自己变弱（符合现实物理）
- 但手上的载体一直在被吃掉
- 传递 = 把火转移到新载体上，计时器重置是物理必然，不是机制让步
- 载体按自身速率持续燃烧，玩家移动不会改变燃料消耗速度

### 公理 II — 氧气即空间
有氧才有火。氧的分布决定火能去哪、你能去哪。
- 密闭空间火会闷灭
- 水下、暴雨绝对不可点燃（做成绝对而非概率，为了可读性）
- 风可见且一致：吹弱火、助强火
- 在代码里它是 **position 的函数**，不是存储的变量

### 公理 III — 火只改变材料，不造成伤害
**火不杀死，火改变。**
- 没有血条，没有连续伤害，只有**离散的状态切换**
- 规则挂在材料上，不挂在物体上（借鉴《旷野之息》）
- 转换不可逆

**材料响应表**（示例，开发中扩展）

| 材料 | 颜色 | 遇火 | 燃尽后 | 湿态 |
|---|---|---|---|---|
| 干木 | 棕 | 3s 后燃烧 | 消失，留下缺口 | 不可燃 |
| 干草 | 黄 | 立即燃烧，快速蔓延 | 灰烬地面，不可再燃 | 不可燃 |
| 金属 | 灰 | 不燃，导热至另一端 | — | 无影响 |
| 湿泥 | 深褐 | 烘烤后硬化为陶 | 可站立平台 | 初始态 |
| 油 | 黑 | 立即燃烧，沿流向蔓延 | 消失 | 浮于水面仍可燃 |
| 藤蔓 | 绿 | 烧断 | 悬吊物坠落 | 不可燃 |

**公理分工**

| | 管什么 | 一句话 |
|---|---|---|
| I | 火自己能活多久 | 稀缺的不是火，是能烧的东西 |
| II | 火能去哪、你能去哪 | 有氧才有火 |
| III | 火对世界做什么 | 火不杀死，火改变 |

I 和 II 是**约束**（制造压力），III 是**能力**（提供解法）。

## 5. 火种状态机与变量模型

### 5.1 两个独立变量

**不为"缺燃料/缺氧/低温"分设三种状态**——那会导致组合爆炸，且玩家在屏幕上分不出来。正确做法是：**一条线性状态机 + 两个独立变量**。

| 变量 | 归属 | 可逆性 | 紧张感类型 |
|---|---|---|---|
| **Fuel** | 载体 | **不可逆**（烧掉回不来） | 必须找到东西 |
| **Oxygen** | 空间（查询） | **瞬时可逆**（走出去就好） | 换个地方 |
| ~~Heat~~ | 派生量 | — | **不参与判定，仅决定火焰颜色** |

温度被砍掉作为独立变量：它的功能被另外两个覆盖（水/雨/寒冷可直接扣燃料或扣氧）。少一个变量 = 少一整类边界情况。

### 5.2 状态机

```
Burning ⇄ Ember → Dying → Extinguished
   ↑________________|
```

| 转移 | 条件 |
|---|---|
| Burning → Ember | fuelRatio < 0.25 或 oxygen < 0.4 |
| Ember → Burning | 两者均回到阈值以上 |
| Ember → Dying | fuelRatio < 0.05 或 oxygen < 0.15 |
| Dying → Burning | 玩家吹火成功（需**空手** + 侧有可燃物） |
| Dying → Extinguished | dyingTimer 归零（约 8s）→ 关卡失败 |

**Ember 与 Dying 的本质区别不是程度，是是否有倒计时。**
- Ember = **稳定态**，可长期维持（陶罐余烬能带很久），是安全形态
- Dying = **倒计时态**，8 秒后终结

**Dying 期间玩家可移动**，移动不会改变倒计时速度。

### 5.3 三个视觉维度

同一个状态，不同成因必须长得不一样。这三个维度互不重叠，可同时表达：

| 视觉维度 | 数据来源 | 表达什么 | 玩家的直觉反应 |
|---|---|---|---|
| **尺寸** | fuelRatio | 还能烧多久 | 找新的可燃物 |
| **浑浊度 / 黑烟** | oxygen | 憋不憋得住 | 换个地方 / 通风 |
| **颜色**（暗红→橙→白） | 派生温度 + legacyColor | 状态 + 经历 | 靠近热源 |
| **闪烁** | isDying | 要死了 | 抢救 |

**legacyColor**：火焰核心混入走过时代的色调，最后一关是多色叠加。玩家看着火苗就能看到走过的路。一个参数的事，但它让"同一团火"在视觉上成立。

## 6. 技术架构

### 6.1 一句话概括

> **火是一个没有位置的逻辑对象，寄居在载体上；燃料属于载体，氧气属于空间；视觉层只读不写。**

### 6.2 四个角色

#### Flame — 那团火（纯逻辑，无 Transform）

全局唯一（因为设定里它就是唯一的）。

**持有**：状态、身份数据（走过的时代、legacyColor）、当前载体引用、dyingTimer
**不持有**：Fuel（在载体上）、Oxygen（是空间的函数）、Position（由载体提供）

```csharp
public class Flame  // 逻辑对象，不挂 Transform
{
    public FlameState State { get; private set; }
    public Color LegacyColor { get; private set; }
    public List<Era> VisitedEras { get; }

    private IFuelCarrier _current;
    private float _dyingTimer;

    public Vector3 Position => _current.GetPosition();
    public float FuelRatio => _current.GetFuelRatio();
    public float Oxygen    => OxygenField.Sample(Position);

    public void Tick(float dt)
    {
        _current.ConsumeFuel(dt, BuildContext());
        Evaluate(FuelRatio, Oxygen, dt);
    }

    // 交接：一行搞定，无需任何数值搬运
    public void AttachTo(IFuelCarrier next)
    {
        _current?.OnDetach();
        _current = next;
        _current.OnAttach();
    }
}
```

**关键**：因为 Fuel 本来就在载体上，交接不需要写任何数值同步代码。这是数据放对地方的回报。

#### IFuelCarrier — 载体接口

火把、篝火、炉膛、油灯、管网、密封舱全部实现它。

```csharp
public interface IFuelCarrier
{
    float   GetFuelRatio();                              // 0..1
    Vector3 GetPosition();
    void    ConsumeFuel(float dt, ConsumeContext ctx);   // 载体自己负责消耗
    void    OnAttach();
    void    OnDetach();
}

public struct ConsumeContext
{
    public float Oxygen;
}
```

- 火把每帧扣自己的长度、更新自己的 mesh 缩放
- **燃料耗尽时不销毁火**，只是 GetFuelRatio() 返回 0，火自己滑向 Dying
- → **载体死，火不死**，设定在代码里成立

#### OxygenField — 空间查询，不是存储

```csharp
public static class OxygenField
{
    public static float Sample(Vector3 pos);  // 0..1，由场景中的 OxygenVolume 叠加插值
}
```

场景布置 `OxygenVolume`：密闭房间 0.3、水下 0、真空 0、通风口 1.2。

**公理 II 说"氧气即空间"，那么在代码里它就应该是 position 的函数。**好处：玩家走进密闭空间火就闷、走出来就恢复，全自动，不需要写任何进出房间的事件逻辑。

#### FlameVFX — 只读的视觉层

订阅 Flame 状态与读数，翻译成粒子参数。Transform 每帧对齐 `flame.Position`。

**它对逻辑一无所知，删掉它游戏照常运行。**这条边界必须守住——一旦 VFX 里出现影响判定的代码，架构就漏了。

### 6.3 依赖关系（无双向依赖）

```
Flame ──读──> IFuelCarrier (Fuel + Position)
  │
  └──读──> OxygenField (Sample by position)

FlameVFX ──读──> Flame (state) + Position

Player ──调用──> Flame.AttachTo() / 吹火
```

### 6.4 架构与公理同构

| 公理 | 数据在哪 | 代码形态 |
|---|---|---|
| I 燃料即时间 | 载体 | `IFuelCarrier.GetFuelRatio()` |
| II 氧气即空间 | 空间 | `OxygenField.Sample(pos)` |
| III 火只改变材料 | 材料表 | 材料响应查表，不在 Flame 内 |
| — 火的身份 | Flame | 唯一贯穿的对象 |

**这张表要写进设计文档第 9 章**：证明类划分是从设计推导出来的，不是随手写的。

### 6.5 工业关：管网只是一个更复杂的载体

```csharp
public class PipeNetwork : MonoBehaviour, IFuelCarrier
{
    // 内部是一张图：节点、边、可燃性、燃烧耗时权重
    private Graph _graph;
    private HashSet<Node> _burningNodes;

    public float   GetFuelRatio() => AggregateFuel();
    public Vector3 GetPosition()  => BurningCentroid();  // 供镜头与 VFX 使用

    // 每 tick 沿可燃边扩张
    private void Spread(float dt) { /* 带权图搜索 */ }

    public void CloseValve(Edge e);   // 切断一条边

}
```

**Flame 依然唯一，它只是换了个载体。**玩家关阀门操作的是图，不是 Flame。

> **工业关没有引入任何新类型，只实现了一个新的 IFuelCarrier。**
> "新增材料而非新增规则"这条纪律，在代码层面同样成立。
> ——这句话原样写进设计文档 2.7 和第 9 章。

### 6.6 一条必须维持的不变式

**火必须始终有载体。**
吹火时玩家需空手，此时火把**落地并仍作为合法 TorchCarrier 存在**，火继续寄居其上，玩家去吹的是柴堆。这样永远不需要处理 `_current == null`。少一类边界，少一类 bug。

### 7.3 石器时代（✅ 实现，约 5 分钟）

**开场**：闪电击中树，原始人第一次拿到火。这是**唯一一次火不是被传递的**——它来自偶然。之后每一次，它都来自某个人的手。

**段落一 · 燃料即时间（教学）**
地上三根长短不一的干木枝，最短那根刚好不够走到对岸。让玩家无痛失败一次，买来对"燃料=时间"的肌肉记忆。木枝长度必须有明显视觉差。

**段落二 · 兽群围猎（战斗）**
狼形几何体把玩家围在开阔地。它们不敢进入火光范围，会绕圈、试探、从背后逼近。**你的防御圈在缩小，而敌人在等。**

玩家两个动作（详见第 9 章）：横扫驱赶 / 突刺点燃。

**胜利条件不是杀光**，是撑到火线合围或退到安全区。**全程没有杀死任何野兽**——保持"火不是武器"的一致性。

**代价机制**：过度用火自保 → 战斗结束时火把只剩很短一截，而洞穴还没到。战斗的代价直接兑现在下一段的燃料上。

**段落三 · 洞穴与最后一步（高潮）**
洞穴内湿冷、火把加速衰减、黑暗中有野兽的眼睛。到达柴堆时火把只剩余烬，不足以点燃巨大的柴堆。

玩家必须投入随身可燃物，然后——**俯身吹火**。这个动作要求他**放下火把、离开火的保护范围**，野兽开始逼近。

火烧起来的瞬间，光炸开，野兽退散。而玩家角色已经站不起来了。

**设计要点**：
- 复用全部所学：燃料有限、余烬可复燃、火需要氧气
- "放下火把"与全关行为准则（永远不要离开火）**完全相反**——规则在最后一刻被玩家自己打破
- 玩家必须**自己按住那个键**。他不是被过场杀死的，他是选择的
- **全关都在教"离开火就会死"**，所以玩家知道自己在做什么。他不是不知情地牺牲，是知道了还是按下去
- **此处不给任何文字提示**（教学期给，高潮期撤掉）。玩家已经学会了。"手里有火把时吹不了"由机制本身告知
- 角色倒下后身体留在原地 → 下一关的遗留物

### 7.4 青铜时代（📄 纸面）

**核心概念**：传递不等于位移。火固定在炉中，热沿金属杆传到别处。**"火在 A，效果在 B"**——这是工业关管网的先修课。

**解谜**：铸造场景。熔化金属、浇铸成型、用铸件搭建通路。玩家调整的是金属杆的连接方式。

**战斗**：对手是**会用火的人**（部落战士），第一次出现对称的敌人。你的优势不在于有火，而在于你的是**那团火**——可以点燃他们武器的木柄、让他们手中的金属过热到握不住。**你攻击的不是人，是他们和火的关系。**

### 7.5 工业时代（✅ 实现，约 5 分钟）

**核心矛盾**：火的危险性与火带来的工业革命。**火会失控。**

**场景**：中央锅炉房，垂直两层。上层走道可俯瞰管网，下层是炉膛、阀门、油罐区。管网从中央锅炉辐射向四个厂房节点。

**全局可读性**：管道受热由灰变红，玩家隔墙可见火的位置与推进方向。**零 HUD**。（复用"温度即颜色"设定，不新增规则）

**段落一 · 点火（教学，承接蒙太奇）**
把火种从篝火取出送进炉膛。这一段完全复用石器关操作，是**故意的舒适区**。

**段落二 · 失控（核心）**
管道接口崩裂，火逃进管网，沿可燃边按最短路径向外扩张。

玩家两种手段（成本—可靠性梯度不同）：
- **关阀门**：切断一条边，耗时约 3s，火会绕路
- **放水**：淹没区域，永久不可燃，但**水会流**，可能淹到你还需要的地方

**关键约束在此第一次被撞上**：管网某处有一个大阀门，关掉能一次性掐断全部火路——但会同时切断炉膛氧气，火会彻底熄灭。系统明确提示"这将熄灭火种"，然后**拒绝执行**。

> 玩家在这一刻理解：**他有能力结束这一切，但他不被允许。**

这一条把战斗和主题焊死：你手上有全套灭火手段，但一样都不能用尽。**这是一场你必须留手的战斗**，而理由完全来自设定，不是设计师的规定。

**段落三 · 抉择（高潮）**
火逼近油罐区，烧到即全灭。通往油罐有两条路径，只来得及堵一条：

- **路径 A**（木质工房）：放水堵路 → 水流进下层淹掉备用煤仓 → **火失去后续燃料**
- **路径 B**（金属主管道）：关阀制造密闭段 → 段内火缺氧衰减 → **火被烧成余烬状态**

**两条都能救下油罐，两条都会伤害火本身。没有全身而退的选项。**

> 这一关的核心陈述：**驾驭这团火的代价，是它不可能毫发无损。而你必须选一种伤害。**

**设计要点**：后果必须在关卡后半段真实兑现，不能只是文案。选 A 的人后面燃料紧张，选 B 的人后面火苗微弱。**玩家自己造成的状态，被他自己带到下一段去。**

**建议**：在火逼近之前给一小段无压力的**观察窗口**，让玩家先看清地形再触发威胁。SSR 式的精密要求玩家有信息，而不是被信息量压垮。

**段落四 · 收束**
火被逼回炉膛，但已经不是刚才那团火。玩家必须重新把它养回来（找残存的煤、重新配氧、余烬则再吹一次——**此处回调石器关，且不需要任何提示**）。

火重新稳定燃烧的瞬间，蒸汽机运转，厂房机械依次启动。镜头拉远，**第一次让玩家看见这团火在驱动整座工厂**。

### 7.6 电气时代（📄 纸面）

**核心概念**：**"关闭"与"熄灭"的区别**。火可以被关掉——它还在，只是暂停了。这是全游戏唯一一次火可以安全地不燃烧。

机制上引入**可逆性**：前四关所有操作都不可逆（烧掉就没了），这一关第一次可以撤销。

**解谜**：由开关、时序、电路构成的系统，让火在正确的时间出现在正确的位置。全五关中最接近传统解谜的一关，节奏上的舒缓段。

**战斗**：对手是机器——不怕火，但怕过热。攻击方式是让它超载。同时机器会尝试**关闭**你的火（对它来说这只是一个待关闭的电路）。

> **恐怖点**：这是唯一一次，火可能不是被扑灭，而是被**关掉**。一个按钮就能让十万年的传递停止。而且它甚至不是恶意的。
> （呼应《地。》：火第一次落入制度手中）

### 7.7 太空时代（✅ 实现，约 2 分钟）

**只做一件事**：把火送进密封舱，注氧，关门，看它离开。**砍掉所有谜题**——这一关是收尾，不是考试。

**核心矛盾恰好是氧气**：真空里火不能燃烧，所以最后一关的挑战不是"带着火跑"，而是**火第一次必须自带氧气才能活下去**。公理 II 在最终关被推到极限，而不是被抛弃。这是收束，不是转折。

注氧操作在舱外，注氧时火在舱内孤立无援。最后一步是关闭舱门——**那意味着你再也碰不到它了**。

**唯一必须做好的一帧**：火箭升空，镜头**第一次跟着火离开**，而玩家角色留在地面。

> 整个游戏镜头都锁定火种，玩家只是恰好在它旁边。最后一刻，火走了，镜头跟着火——**你被留下了**。
> 规则从头到尾没变，但它最后一次执行的结果，就是告别。

## 8. 转场蒙太奇（关卡之间）

**手法**：镜头**绝对不动**。同一堆篝火、同一个机位、同一个焦距。变的只有周围的东西。一旦镜头动了，它就变成了普通过场。

**内容**：中间时代用**剪影而非场景**。几何体人形以极快节奏掠过画面：有人添柴、有人在火边敲打、有人拿走火把又放回、有人带着火跑向远方。每个只出现零点几秒。观众不需要看清，只需要**感到密度**。

**要传达的不是"时代变了"，而是"这团火一秒都没断过"** → 火焰全程持续燃烧、持续可见、始终在画面正中。

**结尾要有停顿**：掠影结束后静止一两秒，火独自燃烧，然后下一个时代的手伸进来。那个停顿是让观众意识到"刚才过去了很久"的地方。

**两段蒙太奇**：
1. 石器 → 工业（跨过青铜，一万年）
2. 工业 → 太空（跨过电气；**最后一个画面是火箭升空**，让 demo 有完整情绪弧线）

成本极低（预设动画的几何体沿路径快速播放 + 环境色调渐变），但**性价比最高的表现片段**。

## 9. 战斗设计

### 9.1 战斗从公理中长出

火不是武器。火是**状态转换器**——作用于敌人时产生"燃烧状态"。

**敌人也是材料**：敌人身上有可燃结构（毛皮、木柄、油污）。火接触它，它进入燃烧状态——**这不是掉血，是状态改变**。

燃烧状态的敌人：狂暴乱窜、撞到同伴会**传染**、冲进干草会**引燃整片**、跳进水里会**恢复**。

> 击败它的方式不是"打够 100 点伤害"，而是**利用这个状态**——点燃它，让它跑向你想要的地方，引发连锁。

**所以战斗和解谜共用同一套规则：两者都是"让火接触正确的东西"。**解谜里正确的东西是湿泥，战斗里是野兽的毛皮。动词完全相同。

**燃烧的敌人不会死**，只会逃跑/失控。全程不杀死任何东西——这让"火不是武器"在玩家的实际体验里成立。

### 9.2 石器关：火把即武器即资源即护送目标

**这一句话就是整份笔试的战斗系统陈述**，三位一体，且只有这个题材能做出来。

两个动作（**只做两个，不做连招、闪避帧、锁定系统**）：

| 动作 | 效果 | 代价 |
|---|---|---|
| **横扫** | 范围驱赶，逼退兽群，不造成伤害 | 只能顾一面，挥的时候背后空了 |
| **突刺点燃** | 命中则敌人进入燃烧状态 | **每次点燃消耗火把长度** |

**核心张力**：每一次攻击都在缩短你的火把，而火把是你唯一的光、唯一的防御、以及必须送到洞穴的东西。

> **这是一个你越战越弱、且失败代价是主题级的战斗系统。**

### 9.3 工业关：失控之火作为对抗因子

**对抗因子不必是生物。**前一关你面对野兽——它怕火，火是你的护身符。这一关关系反转：**火不再听你的**，它在管网里自己跑，你追着它、堵它、改它的道，而它在扩张。

它具备对手的三个特征：
- **有意图**：沿可燃路径朝某个东西推进（油罐、你的退路），可预测
- **你有武器**：关阀门、放水，全部是已有公理的直接应用
- **有输赢判定**：烧到禁区你输，逼回炉膛你赢

**紧张感反转了**：石器关是"我可能失去它"，工业关是"我可能被它吞掉"。同一份重量，恐惧方向相反。而玩家会意识到这两种恐惧其实是同一件事——他仍然在为它的存续负责，只是这次它太大了。

### 9.4 三关战斗的统一原则

> **每一场战斗，你赢了，但它变弱了。**

石器关消耗火把长度，工业关消耗火的健康状态，太空关消耗封装前的时间窗口。

这条写在设计文档第 5 章（设计思路），**不写进第 2 章的机制建模**——它是设计原则，不是物理规则。

## 10. 已砍内容与理由

**砍的判据**：只有"证明公理成立"的东西留下。凡是"让公理更丰富"的，全部进设计文档第 6 章。

| 砍掉的 | 原属 | 理由 |
|---|---|---|
| **青铜关整关** | Demo | 需要导热系统 + 人形敌人 AI，两个都从零开始；它贡献的"传递≠位移"已被工业关管网证明 |
| 投掷火把 | 石器 | 抛出后无防护、要跑去捡、镜头要处理火与人分离，三个动作里最贵 |
| 湿地跳跃段落 | 石器 | 平台跳跃手感是坑；"余烬可复燃"可在战斗中自然发生 |
| 双解法断崖 | 石器 | 需要一套材料转换系统，只为一个谜题不值 |
| 烟驱赶野兽 | 石器 | 边际收益低 |
| 拆地板（第三手段） | 工业 | 边际收益低 |
| **夺阀者 NPC** | 工业 | 最痛的一刀。需要图上决策 AI + 路径竞速手感，整个 demo 最贵单项 |
| 三步点火流程 | 工业 | 简化为一步 |
| 太空关谜题 | 太空 | 收尾不是考试 |

**砍完的账**：石器 5min + 工业 5min + 太空 2min + 两段蒙太奇 ≈ **13 分钟**，超过题目要求的 10 分钟，且三关全部呈现。

**需要实现的系统只有四个**：火焰特效与状态机、火把燃料与战斗、图结构火焰传播、镜头系统。

## 11. 参考作品与借鉴点

**这一节直接对应加分项 4，格式必须是：这部作品的什么机制 / 制造了什么体验 / 我借用了哪个结构 / 改成了什么 / 为什么改。**

### 《史蒂芬的香肠卷》
**借的是公理极少且无特例的纪律，不是推箱子形式。**

它的全部公理只有：叉子固定在身前一格、香肠占两格且滚动、香肠有四个面、面接触烤架就熟、已熟再烤就焦。此外没有任何特例规则。所有深度来自这几条的相互作用。

**在实时 3D 中如何保留这份纪律**：网格和回合原本承担的是"让玩家能预判后果"的功能，实时环境下用别的东西替代——极强的视觉可读性（火焰颜色直接暴露状态）、明确的因果延迟、行为的可预测性（火吃掉载体永远以同一速度发生）。

⚠️ **文档中务必写清"借的是理念不是形式"**，否则会被读成"想做推箱子但做成了动作游戏"。

### 《地。—关于地球的运动—》（鱼豊）
**借的是"主角流动、客体恒定、传递者看不到终点"这个结构。**

落进机制的方式：
- 载体死而火不死
- 每关换人操作
- 失败时火进入余烬而非直接结束
- 每关开场场景里有上一关那个人的遗留物（烧尽的火把、骨骸）——**白模也能做到，零文字，零成本**

**衍生的设计要求**：阻力必须有道理。抢火、灭火的敌人如果只是"坏人"，主题会薄。工业关那个"要扑灭火的人"（虽已砍掉实现）在设定上是**正确的**——他在救火，他不知道这团火是什么。

⚠️ **措辞注意**：不要把它简化成"一代代人传递理想"，那会显得读得浅。只提取那个明确的结构点。

⚠️ **风险提示**：那类作品的力量来自长篇叙事累积，而本 demo 只有 13 分钟、白模、无配音。**把这条叙事线放在设定与结构层，不要放在演出层。**它应体现为机制和关卡结构，**不应**体现为大段文本、独白、或需要读设定才能感受到的东西。

### 《塞尔达传说：旷野之息》
**借的是"规则挂在材料上，不挂在物体上"。**

玩家学一次材料表，就能预测世界上任何一个物体遇火会怎样。这是"乘法"的来源，也是 SSR 那套纪律在 3D 实时里的形态。

## 12. 开发路线图

> 假设总工期约 3 周。工程假设为 **Unity（URP）**，代码骨架为 C#。若用 UE 需相应转译。
> **风险原则**：最独特也最容易翻车的部分（镜头系统）必须早做。

### 阶段 0 · 工程搭建（0.5 天）
- Unity 版本锁定、URP 配置、目录结构
- 白模 Prefab 库（Cube/Capsule/Cylinder）
- **颜色规范表**落地（对应题目第 2 条）
- 建一个 `取舍日志.md`，**从今天开始记**（设计文档第 7 章的价值全在细节，做完再回忆就丢光了）

### 阶段 1 · 火焰核心（1.5 天）⭐ 最优先
- `Flame` + `FlameState` 状态机四态
- `IFuelCarrier` + `TorchCarrier`（火把 mesh 随燃料缩放）
- `OxygenField` + `OxygenVolume`
- `FlameVFX` v1（先只做尺寸变化）
- 吹火复燃动作

**验收标准**：能看见火把变短 → 火变小 → 走进密闭空间火变暗 → 濒熄时吹火复燃。
**这一步做完，核心已可验证，剩下的都是在它上面加载体。**

### 阶段 2 · 镜头系统（1 天）⭐ 最高风险
- 加权中点算法、距离权重曲线、FOV 自适应
- 火脱手时的方向指示
- 过场模式（完全锁定火）
- **必须验证第三人称与锁定火种能否共存**

**降级预案**：若两天内方案不成立，退回标准第三人称 + 火种屏幕边缘指示器，把"镜头聚焦火种"降级为仅用于过场。**这个降级要写进设计文档的取舍记录。**

### 阶段 3 · 角色控制（0.5 天）
- 第三人称移动
- 持火 / 空手两套状态（**持火时哪些操作被禁用**——对应文档 3.3）

### 阶段 4 · 石器关（2 天）
- 白盒关卡搭建
- 兽群 AI（保持在火光半径外、寻找空档突进）
- 两个战斗动作
- 燃烧状态与连锁传播
- 洞穴段落 + 吹火结尾 + 角色倒下

**验收标准**：一个完整可玩的 5 分钟关卡。**到这里 demo 已经有了最低可交付版本。**

### 阶段 5 · 火焰特效打磨（1 天）
- 三维度参数化（尺寸 / 浑浊度 / 颜色）
- legacyColor 系统
- 所有火共用同一套资产验证

### 阶段 6 · 工业关（2.5 天）
- `PipeNetwork` 图结构 + 扩张算法
