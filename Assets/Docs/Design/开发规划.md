### 阶段 1 · 火焰核心（1.5 天）⭐ 最优先 ✅ 已验收（2026-09-04）

**目标**：三条公理里的前两条在游戏里都能被看见、被玩坏、被救回来。

#### 1.1 状态机与载体 ✅

- ✅ `Flame` 逻辑单例（私有构造，`Instance` 编译期唯一）
- ✅ 四态 `Burning / Ember / Dying / Extinguished`，**绝对阈值**：`fuel<10`、`oxygen<6`、`fuel<5`、`oxygen<2`、`dyingDuration=8s`
- ✅ 降级判定排在恢复判定之前（否则 Ember 会在同一帧被判回 Burning）
- ✅ `Carrier` 抽象基类：`Fuel` / `Position` / `ConsumeFuel` / `OnAttach` / `OnDetach`
- ✅ **燃料由载体自己在 `Update` 里扣**，`Flame` 只读不写（初稿：fuel 保存在载体上）
- ✅ 未点燃的载体不自燃（`isLit` 闸门）——否则场上备用火把会自己烧光
- ✅ `Torch`：顶端挂点、杆体随燃料缩短、碰撞传火
- ✅ `FlameRunner`：`LateUpdate` 驱动（等所有载体这一帧扣完再判状态，避免慢一帧），并暴露 `onExtinguished` 供关卡接失败重开
- ✅ 载体自毁：fuel 归 0 → 火同帧 Extinguished → `OnDetach` 里 Destroy（销毁放在 Flame 放手之后，避免悬空引用）

#### 1.2 氧气支路 ✅

- ✅ `OxygenZone.cs`：`[SerializeField] float oxygen`，只读属性，`[RequireComponent(Collider)]` + OnValidate 检查 Is Trigger + Gizmo 可视化
- ✅ 区域切换：**由区域检测载体**（`OxygenZone.OnTriggerEnter/Exit` → `carrier.EnterZone/ExitZone`）
  - ⚠️ 与本节原计划（"载体身上的 trigger 更新 Flame 的当前区域"）相反，改的理由有二：
    1. `Torch` 已有自己的 `OnTriggerEnter`（传火用）。在 `Carrier` 基类再写一个会被子类**静默覆盖**，Unity 只调最派生的那个，不报错
    2. 火交接到新载体时，新载体早已在区域内，不会再触发 Enter，`Flame` 会攥着旧区域
  - 结果：`Torch` 一行未改；区域引用存在**载体**身上，`Flame.Oxygen => currentCarrier.Oxygen`，与 `Fuel` 完全对称，交接零同步代码
  - 区域归属**不判 `isLit`**：在哪个房间是载体的客观属性，与点没点燃无关
- ✅ 兜底改为**代码常量** `OxygenZone.DefaultOxygen = 10f`，不再要求场景最外层放大 zone
  - 理由：场景物体会被误删、会忘了放，常量不会。哪一关的"外面"不是露天（太空关外面是真空），那一关自己套一个大 zone 盖掉
  - 多区域重叠时**后进入者优先**；读取时倒序跳过已销毁的 zone（Unity 伪 null）
- ✅ `Flame.Oxygen` 的硬编码 `10f` 已替换
- ✅ 初版数值（露天 10 / 密闭 `Zone_Cave` 5 / 深处 `Zone_Deep` 1.5 / 真空 `Zone_Vacuum` 0）
- ✅ 场景装配与验收（2026-09-03 通过）
  - ✅ 进 `Zone_Cave` → `Burning → Ember`，成因"氧气不足"，`fuel` 全程不动
  - ✅ 进 `Zone_Deep` → `Ember → Dying`
  - ✅ 退回 `Zone_Cave` → `oxygen` 回到 5.0 **而非兜底值 10.0**（重叠栈成立）
  - ✅ 停在 `Zone_Deep` 不动 → 8s 后 `Extinguished`，成因"濒熄倒计时走完"
  - ✅ 进 `Zone_Vacuum` → **立刻** `Extinguished`，成因"氧气归零"，不走倒计时
- ✅ 调试可读性：状态迁移日志带**成因**（燃料 / 氧气 / 两者）与当帧两个读数；区域进出打 `[Zone]` 日志
  - 没有成因的日志分不出"因燃料"还是"因氧气"，阶段 4 调参会反复卡在这里
- ✅ **`FlameDebugHUD`（IMGUI 调试面板）取代翻 Console**，`Flame.ConsoleLog` 默认关
  - 显示：状态 + 最近成因 / 载体与燃料条（画出 `EmberFuel`、`DyingFuel` 两条阈值刻度）/ 氧气条与**整摞区域栈** / 濒熄倒计时 / 吹火进度 / 自动 diff 出的事件日志。F1 开关
  - 用 IMGUI 而非 Canvas：不需要任何资产与预制体，一个脚本拖上去就能用，删的时候删一个文件——**调试工具就该能整块拔掉**
  - 和 `FlameVisual` 一样是只读层：事件日志靠自己每帧比对上一帧推断，`Flame` 侧不为它加任何事件或回调
  - 区域栈是关键显示项：只看最终 `oxygen` 值，看不出"退出小区域是否正确回到大区域"

**验收**：走进密闭房间 → 火降级；走出来 → 恢复。全程不写任何"进出房间"的玩法事件。✅

#### 1.3.2 火焰挂点：从手填魔数改为代码计算 ✅

**症状**：火苗开局悬在杆顶上方；杆体缩短时火苗下降速度约为杆顶的两倍。

**根因**：`FlamePosition` 原先挂在 `Stick` 底下靠继承缩放自动下降，其 `localPosition.y` 必须等于杆体网格的顶面高度。装配指引按 Cylinder 给了 `1.0`，实际用的是 **Cube（顶面 0.5）**——差一倍，于是两者都乘同一个 `localScale.y` 时下降速率差一倍。

**修法**（不是把 1.0 改成 0.5）：
- 从网格包围盒读 `bounds.max.y` / `bounds.min.y`（用 max/min 而非 extents，兼容包围盒不居中的美术模型）
- `ApplyLength` 用 `stick.TransformPoint(0, topLocalY, 0)` 算杆顶世界坐标，缩放与旋转由 `TransformPoint` 带上
- `flamePosition` 降级为**纯可视化 + 阶段 5 的粒子锚点**，位置由代码写入；留空也能跑
- 挂点移出 `Stick`，改挂 `Torch` 根节点——顺带避免阶段 5 的粒子特效被杆体缩放压扁；`OnValidate` 会检查这一点
- 新增 `flameLift`（世界单位，不随杆体缩放）用于微调火苗核心比灯芯高多少

> **教训**：凡是"设计师手填的值必须和资产的某个属性保持一致"，就是一个迟早会静默错掉的魔数。代码已经能读到那个属性时，就该由代码去写。

#### 1.3.3 区域列表允许重复（潜在 bug）✅

一个载体可能挂多个碰撞体（根节点 trigger + 杆体 collider），进同一区域会收到多次 `OnTriggerEnter`。原先 `EnterZone` 去重，导致**任一碰撞体先离开就删掉整条记录**，另一个还在区域内却没人记得 → 火会莫名"恢复"。

改为**允许重复**：列表天然成为计数器，进几次记几笔、出几次删几笔，全出完才算离开，而"后进入者优先"不需要额外代码即照旧成立。日志仍只在首次进入/彻底离开时打印。

> 当前未暴露只是因为验收路径是"离开 Deep 回到 Cave"，`Remove(Deep)` 后 `[Cave]` 恰好正确。

#### 1.3.1 顺带修掉的 bug ✅

**两条熄灭路径不一致**：硬熄灭（fuel/oxygen 归零）会 `OnDetach` 并放开载体引用，倒计时熄灭（`dyingTimer` 归零）**只改了状态**。后果是火灭之后载体的 `isLit` 仍为 true，继续在自己的 `Update` 里烧燃料、继续缩短。

修法不是给漏掉的那条补一行，而是**合并成唯一出口** `Flame.Extinguish(reason)`：记录 `lastKnownPosition` → 改状态 → `OnDetach` → 引用置 null。

同时把"熄灭后 `currentCarrier` 为 null"这个唯一的 null 窗口在 `Flame` 内部消化掉（`VisualPosition` / `Fuel` / `Oxygen` 全部安全返回，另加 `HasCarrier`），镜头与视觉层不需要各判一次空。

- ✅ **燃料按秒扣**（`BlowFuelPerSecond = 2`，吹满一次共 3 点），不是成功时一次性扣：
  1. 中途松手也已经烧掉了，符合"Fuel 不可逆"——放弃要付钱

**走一遍**：火把变短 → 火变小 → 进密闭空间火变暗 → 濒熄时吹火复燃 → 烧尽前交接成功则火延续，没接上则熄灭失败。

**阶段 1 回顾——三个值得记住的模式**（已写进 [`CLAUDE.md`](../../../CLAUDE.md)）：

1. **数据放对地方，就不用写搬运代码。** fuel 在载体、oxygen 在区域，于是火交接载体时零同步代码，区域重叠时零特判。
2. **同一件事有两条路径，就合并成一个出口。** 两条熄灭路径各写各的，漏掉的那条不是"补一行"能修好的（1.3.1）。
3. **手填的值必须和资产属性保持一致时，那就是个迟早静默错掉的魔数。** 代码能读到那个属性，就该由代码写（1.3.2）。

#### 2.1 装 Cinemachine ⬜ 作者做一次

#### 2.2 两台 vcam，零切换器代码 ✅

**切镜头 = 开关过场那台 vcam 的物体。** 没有切换器类，没有 enum，没有 API 调用。

- 常态机位 `CM_FollowPlayer`：Priority **低**、**一直开着**，永远兜底
- 过场机位 `CM_LockOnFlame`：Priority **高**、**默认关着**；打开就自动接管，关掉就自动退回
- 中间的推镜由 CinemachineBrain 的 Blend 负责
- 于是阶段 7 的过场触发是 UnityEvent 直接拖 `GameObject.SetActive`——**一行代码都不用写**
- 工业关要加"拉远看全厂"的机位，也是同样的加法：多一台高 priority 的 vcam，默认关着

> **2026-09-05 修正：删掉了 `Hold` 机位和 `CameraDirector` 切换器（详见取舍日志）。**
> `Hold`（蒙太奇用的固定机位）是我自己加出来的第三种模式，而本节原计划写的就是
> **一个**过场模式「完全锁定火，用于蒙太奇与太空关最后一帧」。
> 蒙太奇里火本来就不动（简报 8 章：同一堆篝火、同一个机位），
> 锚点是火的 `LockOnFlame` 自然就不动——**"镜头绝对不动"是它的结果，不需要另造一个模式。**
> 只剩两台之后，切换器也没什么可切的了，一并删掉。

**手写版的东西现在归谁**（这张表就是这次换方案的全部内容）：

| 原来在 `GameCamera.cs` 里 | 现在在哪 |
|---|---|
| `SmoothDamp` 锚点 | Orbital Follow ▸ **Damping** |
| yaw / pitch / 灵敏度 / 上下夹角 | Orbital Follow ▸ **Horizontal & Vertical Axis** + **Input Axis Controller** |
| `distance` | Orbital Follow ▸ **Radius** |
| `SphereCast` 防穿墙（含忽略 trigger） | **Deoccluder** ▸ Collide Against 用 **Layer** 排除 |
| 切模式的过渡 | CinemachineBrain ▸ **Default Blend / Custom Blends** |
| 三种模式 + 切换器 | 两台 vcam，开关过场那台的物体 |

#### 2.5 场景装配 ⬜ 待作者在 Unity 里做

**这一节本身就是这次的主要交付物**——镜头能不能调，取决于这些参数摆在哪。

**a. 先建两个 Layer**（Edit ▸ Project Settings ▸ Tags and Layers）

- ⬜ `Player`、`Zone`
- ⬜ 三个 `Zone_*` 物体的 Layer 改成 `Zone`；玩家胶囊改成 `Player`
- 理由：Deoccluder 要按 Layer 排除它们。`OxygenZone` 全是 trigger 且罩住整个房间，
  不排除的话玩家一进洞穴镜头就被区域体积顶到脸上——一条谁都没设计过的隐性规则
- 比手写版的 `QueryTriggerInteraction.Ignore` 好在：**显式、在 Inspector 里看得见，
  而且阶段 3 玩家挂上 CharacterController 之后依然成立**（手写版当时要求"删掉玩家的 Collider"，那撑不到阶段 3）

**b. Main Camera**

- ⬜ 加组件 `CinemachineBrain`
- ⬜ 保留 `FlameOffscreenIndicator`（不用改任何引用）
- ⬜ Brain ▸ Default Blend 先用 `Ease In Out, 1.5s`（过场是推镜，慢才有分量）

**c. `CameraRig` 空物体，两个子物体各挂一台 `CinemachineCamera`**（**不要挂在 Main Camera 底下**，位置会自激）

| vcam | Priority / 启用 | 组件 | 关键参数 |
|---|---|---|---|
| `CM_FollowPlayer` | `10`<br>**开着** | Tracking Target = `Player`<br>Position Control = **Orbital Follow**<br>Rotation Control = **Rotation Composer**<br>+ **Input Axis Controller**<br>+ **Deoccluder** | Orbit Style `Sphere`、Radius `5`<br>Vertical Axis range 约 `-25 ~ 70`（火常在地上，要看得下去）<br>Deoccluder ▸ Collide Against **不勾** `Player` / `Zone`，Camera Radius `0.25` |
| `CM_LockOnFlame` | `20`<br>**⚠️ 物体默认关掉** | Tracking Target = **`FlameVisual`**<br>Position Control = **Follow**<br>Rotation Control = **Rotation Composer** | 火没有 Transform（逻辑单例），但 `FlameVisual` 每帧把自己贴到 `Flame.VisualPosition`——**直接指它即可，零代码** |
