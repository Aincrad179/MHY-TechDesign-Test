## I.核心火种机制

核心火种机制：持续消耗燃料（时间）；需要通风/氧气（空间）；可以改变其他物体。

燃料和氧气实际为独立浮点数变量，任何一个值低于阈值都会使火种下降一个强度，任何一个值归0则火种直接熄灭。
1.fuel值保存在载体上，物体燃烧时随时间缓慢减少，是驱动玩家行动的第一要素。
2.oxygen值保存在区域中，只能被读取

火种有四个状态（强度）：Burning（明火）→ Ember（余烬）→ Dying（濒熄）→ Extinguished（熄灭）

> 状态切换逻辑：
> 
> Burning → Ember : fuelRatio < 0.25 或 oxygen < 0.4
> Ember → Burning : 两者均回到阈值以上
> Ember → Dying   : fuelRatio < 0.05 或 oxygen < 0.15
> Dying → Burning : 玩家吹火成功（需空手 + 有可燃物在侧）
> Dying → Extinguished : dyingTimer 归零 → 游戏失败

## 技术实现

### 火种实现架构

Flame.cs：单例对象，不挂在物体上。包含火种状态机，身份数据（例如走过的时代、legacyColor），以及"当前在哪个载体上"的引用。每帧查询Fuel和Oxygen值，决定是否切换状态。

IFuelSource.cs：载体接口。挂载于火把，油灯等载体上。持有并负责修改自己的fuel值，fuel值归0销毁自己。脚本内用flame.AttachTo(newCarrier)转移火种。

oxygen值：环境常量。由Flame.cs每帧查询。例如curentOxygen == currentZone.oxygen

FlameVFX.cs：控制特效。查询Flame的状态和参数，转换成控制粒子特效的参数
