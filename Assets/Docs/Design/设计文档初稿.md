## I.核心火种机制

核心火种机制：持续消耗燃料（时间）；需要通风/氧气（空间）；可以改变其他物体。

燃料和氧气实际为独立浮点数变量，任何一个值低于阈值都会使火种下降一个强度，任何一个值归0则火种直接熄灭。
1.fuel值保存在载体上，物体燃烧时随时间缓慢减少，是驱动玩家行动的第一要素。
2.oxygen值保存在区域中，只能被读取

火种有四个状态（强度）：Burning（明火）→ Ember（余烬）→ Dying（濒熄）→ Extinguished（熄灭）
 
> 状态切换逻辑：
> 
> Burning → Ember : fuel < 10 或 oxygen < 6
> Ember → Burning : 两者均回到阈值以上
> Ember → Dying   : fuel < 5 或 oxygen < 2
> Dying → Burning : 玩家吹火，吹火时无法移动，且额外消耗一定fuel值
> Dying → Extinguished : dyingTimer 归零 → 游戏失败

两个变量的性质不同，这是它们不能合并成一个"生命值"的原因：

| | fuel | oxygen |
|---|---|---|
| 存在哪 | 载体 | 区域 |
| 谁能改 | 载体自己 | 没人，只能读 |
| 可逆性 | 不可逆，烧掉回不来 | 瞬时可逆，走出去就好 |
| 玩家的应对 | 去找东西 | 换个地方 |

### 熄灭

熄灭只有两条路径，且都收束到同一个出口：

1. **硬熄灭**：fuel 或 oxygen 归 0 → 立即熄灭，不走倒计时
2. **倒计时熄灭**：Dying 状态下 dyingTimer 归零

两条路径都必须做同一组收尾：记录熄灭位置 → 置 Extinguished → 载体 OnDetach → 放开载体引用。任何一条漏做收尾，载体都会在火已经灭了之后继续烧自己的燃料。

因为 fuel 归 0 走的是硬熄灭，dyingTimer 那 8 秒的抢救窗口**实际只对缺氧成因有效**。燃料是不可逆的，烧完就是烧完。

### 吹火

吹火是 Dying 唯一的出路。

- **按住**触发，不是按一下。按住期间玩家无法移动
- 按住期间**每秒**扣额外燃料，不是成功时一次性扣。中途松手已经烧掉的不退——放弃也要付代价
- dyingTimer **不暂停**。所以吹火是场赛跑：得在倒计时烧完前吹满
- 吹到 fuel 归 0 则直接熄灭。这不是特例，是硬熄灭规则自然生效
- 成功后置 Burning，但**不豁免后续判定**：燃料仍低于阈值就会被打回 Ember。吹火买的是"脱离倒计时"，不是"回到满血"

由此，因燃料不足而濒熄时吹火几乎必然是死路——你在用最后的燃料换一瞬。吹火本质上是**缺氧那一类困境的解药**。石器关洞穴高潮要求玩家先投入随身可燃物再吹，原因就在这里。

### 氧气与区域

oxygen 是区域上的常量，不是连续场。一个区域一个值，进出即切换。

- 区域重叠时**后进入者优先**（走进大房间里的小密室取小密室，退出来自动回到大房间）
- 任何位置都必须取得到值。兜底放在代码里的默认常量，不依赖场景里摆一个大区域——场景物体会被误删、会忘了放
- 哪一关的"外面"不是露天（太空关外面是真空），那一关自己套一个大区域盖掉

## 技术实现

### 火种实现架构

Flame.cs：单例对象，不挂在物体上。包含火种状态机，身份数据（例如走过的时代、legacyColor —— 设定保留，留待后续实现，核心循环跑通前不写），以及"当前在哪个载体上"的引用。每帧查询Fuel和Oxygen值，决定是否切换状态。

Carrier.cs：载体大类。火把，油灯等小类继承于大类并挂载在object上。持有并负责修改自己的fuel值，fuel值归0销毁自己。（`Fuel`、`Position`、`ConsumeFuel`、`OnAttach`/`OnDetach`）

oxygen值：环境常量。由Flame.cs每帧查询。例如 currentOxygen == currentZone.oxygen

FlameVisual.cs：控制特效。查询Flame的状态和参数，转换成控制粒子特效的参数

FlameRunner.cs：场景侧驱动器。Flame 不是 MonoBehaviour、自己没有 Update，必须有人每帧推它一次，就是这个类。它同时是"火灭了之后做什么"的挂点——Flame 只负责判定状态，失败重开是关卡的事。放在 LateUpdate：载体在自己的 Update 里扣燃料，Unity 不保证脚本间的 Update 顺序，等这一帧所有载体都扣完再判状态，读到的就永远是当前帧的值。

OxygenZone.cs：区域常量 + 范围。由**区域检测载体**（区域的 trigger 找到进来的 Carrier），不是载体检测区域。两个原因：载体子类可能已经占用了 OnTriggerEnter，在基类再写一个会被静默覆盖；火交接到新载体时新载体早已在区域内，不会再触发一次 Enter。

### 数据归属

这是整套架构唯一需要记住的一句话：

> 火是一个没有 Transform 的逻辑单例，寄居在载体上；燃料属于载体，氧气属于区域，视觉层只读不写。

因此：

- `Flame.Fuel` 读的是 `currentCarrier.Fuel`
- `Flame.Oxygen` 读的是 `currentCarrier` 转告的区域值
- 火交接载体时**不需要写任何数值搬运代码**，因为数值本来就不在 Flame 手里
- "火已熄灭"是载体引用唯一为 null 的窗口，这个窗口在 Flame 内部消化掉，镜头和视觉层不该各判一次空

### 火种燃烧逻辑

不管载体，每秒固定消耗1fuel值

不同载体fuel值不同

### 载体逻辑

火把：火焰在火把顶端烧。剩余燃料=火把长度，火把长度随着燃料减少而缩短

- 杆体缩短时**底端钉在原地**，只有顶端往下退
- 火焰挂点由代码从杆体网格的包围盒算出，不由手工填写。挂点必须落在杆顶是几何事实，不是摆位品味
- 未被点燃的载体不烧自己的燃料，否则场上的备用火把会自己烧光
- 载体只在 fuel 归 0 时销毁自己。交接给下一个载体时 fuel 还有剩，载体留在场上，掉地上还能再点

### 参数

阶段 1 实测值，均待手感调整。

| 参数 | 值 | 说明 |
|---|---|---|
| 火把 fuelCapacity | 30 | 约 30 秒 |
| burnRate | 1 /s | 所有载体统一 |
| Ember 阈值 | fuel < 10 / oxygen < 6 | |
| Dying 阈值 | fuel < 5 / oxygen < 2 | |
| dyingDuration | 8 s | 只有缺氧成因跑得满 |
| 吹火时长 | 1.5 s | 按住 |
| 吹火燃料消耗 | 2 /s（共 3） | 够疼但不必死 |
| 区域 oxygen | 露天 10 / 密闭 5 / 深处 1.5 / 真空 0 | 兜底值 = 露天 10 |

**最关键的比值尚未确定**：一根标准火把的燃烧时长 ÷ 走完一个典型房间的时长。它决定整体紧张度，其他数值都跟着它调。
